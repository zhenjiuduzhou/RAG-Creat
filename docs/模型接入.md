# RAG Studio 模型接入

点击项目右上方「模型设置」，选择模型来源，点击「测试并应用」。模型维度自动检测。更换模型、前缀或模型版本后重新构建；旧索引在重建成功前保留。

## 内置模型如何安装

默认使用 intfloat/multilingual-e5-small。首次构建或测试内置模型时从 Hugging Face 下载到 `dist\RAGStudioDate\models\multilingual-e5-small`，随后直接读取本地目录；模型不是装在 EXE 里面。开发依赖和运行库已随 dist 交付。首次下载需要联网，以后可离线使用。

## 外部 Embedding API

选择「远程 API」，填 `/v1/embeddings` 完整地址、服务端实际模型 ID 和 API Key。可以使用 OpenAI 兼容的云服务，也可以对接本机 Ollama、vLLM 等服务。不是聊天 completion API，不能填写普通聊天模型端点。

例：OpenAI 地址 `https://api.openai.com/v1/embeddings`、模型 `text-embedding-3-small`。本机兼容服务示例 `http://127.0.0.1:11434/v1/embeddings`，模型填本机已安装的 embedding 模型名。供应商服务地址和支持模型以其控制台为准。网络地址要求 HTTPS；明文 HTTP 仅允许本机 loopback。

请求格式：`{"model":"模型名","input":["文档片段"]}`。响应格式：`{"data":[{"index":0,"embedding":[0.1,0.2]}]}`。程序检查数量、维度与非有限数值，再做 L2 归一化。构建和查询都调用同一个模型。模型版本栏记录部署版本；供应商同名模型替换后请修改版本并重建。

API 无本地 tokenizer，按字符保守切分（目标384字符、重叠48字符），并受设置的输入上限约束；这不等于服务商的精确 token 数。大多数模型前缀留空；E5 一般用 query: 和 passage: ，请以模型文档为准。API 模式可能产生请求费用，资料片段和问题会发给配置的模型服务，云端 API 不能断网运行。

密钥使用当前 Windows 用户的 DPAPI 加密保存在数据目录 credentials.json。项目和 manifest 不含密钥；输入框留空可沿用同服务同模型的已存密钥。也可通过环境变量 RAG_STUDIO_EMBEDDING_KEY 设置。交付给客户后，需要在客户机器重新配置密钥。

模型测试通过表示单条请求可用；知识库构建默认批量发送最多 16 条文本。如果服务返回重复、缺失或越界的批量索引，程序会丢弃该批响应并自动改为逐条请求，以确保文本与向量对应正确；这会增加请求次数和构建耗时。单条响应仍需通过索引和向量校验。

## 更换或更新本地模型

1. 从模型提供方下载完整的 Sentence Transformers 模型目录，包括 modules.json、权重、配置、tokenizer 和许可证。或在另一 Python 项目用 SentenceTransformer(...).save(目录) 保存。
2. 选择「本地模型目录」，选中这个目录，按模型说明填写前缀并测试。
3. 程序将目录复制到 `dist\RAGStudioDate\models` 中的独立快照，其他项目不会被覆盖。支持不同向量维度，使用 CPU 推理。
4. 更新时导入新的目录并重新构建。不要直接覆盖已经用于构建知识库的权重文件。

目前支持标准 Transformer、Pooling、Normalize 模块；需要自定义 Python 模块、GGUF 或其他推理框架的模型，请在自己的项目启动 OpenAI 兼容 embeddings 服务，再以「远程 API」接入本机地址。程序不执行模型目录中的自定义代码。较大的模型会增加内存、磁盘占用和构建耗时，交付前确认模型允许企业使用和再分发。

## 工作流接入

工作流仍然调用 RAG Studio 检索服务的 /search 或 /retrieval；模型 API 是检索服务背后的向量计算服务，两者不同。API 模型交付包不会包含模型权重或密钥，客户启动检索服务前设置 RAG_STUDIO_EMBEDDING_KEY；RAG_STUDIO_TOKEN 是工作流访问检索服务的另一个令牌。

## 给客户部署及接入聊天大模型

构建使用的是嵌入模型。回答问题的聊天大模型（LLM）由 Dify、Coze 或自己的应用另行配置。流程：用户问题 → HTTP 知识库检索 → 取 results 中的 text/source/location → 作为上下文发给聊天大模型 → 回答并标注来源。/search 与 /retrieval 返回资料片段，不直接生成回答。

客户交付时导出 Windows 完整包，复制到 Windows 服务器并解压，仍然运行 start_windows.cmd。本地模型包会自动加载随包模型；API 模式会自动读取构建时的服务地址、模型名、版本和前缀，客户只需补充密钥。若原地址是127.0.0.1，该地址指服务器自身，服务器也要安装对应的模型服务；想改成别的模型地址时，请在制作端更新设置、重建并重新交付。

同一客户内网的工作流：在服务启动终端设置 RAG_STUDIO_TOKEN，再运行 `start_windows.cmd --host 0.0.0.0 --port 8765`，工作流填写 `http://服务器内网IP:8765` 和访问令牌。服务器防火墙需要允许指定客户网段访问该端口。只监听默认127.0.0.1时，其他机器不能连接。

云端工作流：部署到云工作流可达的服务器，或使用客户已有VPN/受控隧道。公司内网服务器没有公网访问路径时，云端无法直接连接。内网穿透是其中一种连接方式，不是同内网使用的必要条件。对公网开放应经过HTTPS网关和访问控制，而不是直接暴露未保护的端口。

服务器要求：目前交付的检索服务是Windows EXE，不是Linux程序。Linux部署可使用开发者包搭配Python和服务管理器。运行中的命令窗口关闭会停止服务；长期生产部署请由客户运维将程序注册为Windows服务或设为受管理的后台进程，配置重启、日志与备份。
